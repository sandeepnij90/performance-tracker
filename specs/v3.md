# v3 Spec: Calendar View, Edit Any Entry, Backfill

## Overview

v3 adds two major UX features on top of the multi-user foundation from v2:

1. **Calendar view** on the `/history` page — togglable with the existing list view. Days with entries show a dot indicator. Future days are disabled.
2. **Edit any past entry** — currently only today's entry can be edited. v3 allows editing (and creating) entries for any past date via a day modal.

**User decisions:**
- Calendar lives on `/history` as a toggle (list ↔ calendar)
- Clicking a calendar day opens a modal overlay
- Backfill is allowed — users can create entries for past dates they missed

## Architecture Changes

### New Problem: `date` vs `createdAt`

The current schema uses `createdAt` (actual insert time) as the source of truth for "which day is this entry for." This works fine when entries are always created on the same day they represent. But backfill breaks this: a user creating an entry today for last Tuesday needs a way to record "this entry is for March 10" without changing when it was inserted.

**Solution:** Add a `date DateTime` field (normalized to midnight UTC) as the explicit "intended date" for the entry. `createdAt` remains untouched as the actual insertion timestamp. All display, querying, and deduplication uses `date`.

### One Entry Per Day

The current schema has no unique constraint. Add `@@unique([userId, date])` to enforce one entry per user per calendar day.

## Phase 1 — Schema + Data Layer

### 1.1 New Utility Files

**Create `lib/dates.ts`:**

```typescript
// Normalize a Date to midnight UTC for its calendar date
export function toMidnightUTC(date: Date): Date {
  return new Date(Date.UTC(
    date.getUTCFullYear(),
    date.getUTCMonth(),
    date.getUTCDate()
  ));
}

// "March 18, 2026"
export function formatEntryDate(date: Date | string): string {
  const d = typeof date === "string" ? new Date(date) : date;
  return d.toLocaleDateString("en-US", {
    year: "numeric",
    month: "long",
    day: "numeric",
    timeZone: "UTC",
  });
}

// "Mar 18"
export function formatShortDate(date: Date | string): string {
  const d = typeof date === "string" ? new Date(date) : date;
  return d.toLocaleDateString("en-US", {
    month: "short",
    day: "numeric",
    timeZone: "UTC",
  });
}
```

**Create `lib/types.ts`** — shared interface used across all components and routes:

```typescript
export interface EnergyEntry {
  id: number;
  date: string;           // ISO string, midnight UTC — the intended calendar date
  createdAt: string;      // ISO string — actual insertion timestamp
  mentalEnergy: number;
  mentalNote: string | null;
  physicalEnergy: number;
  physicalNote: string | null;
}
```

This replaces the local `Entry` type defined separately in `CheckInForm.tsx`, `TodayView.tsx`, and `EntryCard.tsx`.

### 1.2 Prisma Schema

Update `prisma/schema.prisma`:

```prisma
model EnergyEntry {
  id             Int      @id @default(autoincrement())
  date           DateTime                            // new: intended date, midnight UTC
  createdAt      DateTime @default(now())            // unchanged: actual insert time
  mentalEnergy   Int
  mentalNote     String?
  physicalEnergy Int
  physicalNote   String?
  userId         String
  user           User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, date])                           // new: one entry per user per date
  @@index([userId, date])                            // updated (was [userId, createdAt])
}
```

### 1.3 Migration

Before running the migration, check for duplicate dates in existing data (would cause the unique constraint to fail):

```sql
SELECT "userId", DATE_TRUNC('day', "createdAt" AT TIME ZONE 'UTC') AS d, COUNT(*)
FROM "EnergyEntry"
GROUP BY "userId", d
HAVING COUNT(*) > 1;
```

If duplicates exist: keep only the row with the highest `createdAt` per `(userId, date)` and delete the rest before proceeding.

The migration SQL (write as a Prisma custom migration):

```sql
-- Add date column as nullable first
ALTER TABLE "EnergyEntry" ADD COLUMN "date" TIMESTAMP(3);

-- Backfill: set date to midnight UTC of existing createdAt
UPDATE "EnergyEntry"
SET "date" = DATE_TRUNC('day', "createdAt" AT TIME ZONE 'UTC');

-- Make date NOT NULL
ALTER TABLE "EnergyEntry" ALTER COLUMN "date" SET NOT NULL;

-- Drop old index on createdAt
DROP INDEX IF EXISTS "EnergyEntry_userId_createdAt_idx";

-- Add unique constraint
ALTER TABLE "EnergyEntry"
  ADD CONSTRAINT "EnergyEntry_userId_date_key" UNIQUE ("userId", "date");

-- Create new index on date
CREATE INDEX "EnergyEntry_userId_date_idx" ON "EnergyEntry"("userId", "date");
```

Run `npx prisma generate` after applying the migration.

### 1.4 `lib/db.ts` Changes

**Update `createEntry`** — add optional `date` param:

```typescript
export async function createEntry(
  userId: string,
  data: { mentalEnergy: number; mentalNote: string | null; physicalEnergy: number; physicalNote: string | null },
  date?: Date
) {
  const entryDate = date ?? toMidnightUTC(new Date());
  return prisma.energyEntry.create({
    data: { ...data, userId, date: entryDate },
  });
}
```

**Update `getTodayEntry`** — use `findUnique` on the unique key (was a date-range `findFirst`):

```typescript
export async function getTodayEntry(userId: string) {
  const today = toMidnightUTC(new Date());
  return prisma.energyEntry.findUnique({
    where: { userId_date: { userId, date: today } },
  });
}
```

**Update `getAllEntries`** — add optional `month` filter, order by `date` (not `createdAt`):

```typescript
export async function getAllEntries(userId: string, month?: string) {
  const where: Prisma.EnergyEntryWhereInput = { userId };
  if (month) {
    const [year, mon] = month.split("-").map(Number);
    const start = new Date(Date.UTC(year, mon - 1, 1));
    const end = new Date(Date.UTC(year, mon, 1));  // exclusive
    where.date = { gte: start, lt: end };
  }
  return prisma.energyEntry.findMany({
    where,
    orderBy: { date: "desc" },
  });
}
```

**Update `updateTodayEntry`** — delegate to new `updateEntryById`:

```typescript
export async function updateTodayEntry(
  userId: string,
  data: { mentalEnergy: number; mentalNote: string | null; physicalEnergy: number; physicalNote: string | null }
) {
  const entry = await getTodayEntry(userId);
  if (!entry) return null;
  return updateEntryById(userId, entry.id, data);
}
```

**New: `updateEntryById`** — edit any entry by ID with ownership enforced:

```typescript
export async function updateEntryById(
  userId: string,
  id: number,
  data: { mentalEnergy: number; mentalNote: string | null; physicalEnergy: number; physicalNote: string | null }
) {
  // Prisma's where: { id, userId } ensures a user can only edit their own entries.
  // Throws PrismaClientKnownRequestError (P2025) if not found or wrong user.
  return prisma.energyEntry.update({
    where: { id, userId },
    data,
  });
}
```

**New: `getEntryByDate`** — fetch an entry for a specific calendar date:

```typescript
export async function getEntryByDate(userId: string, date: Date) {
  return prisma.energyEntry.findUnique({
    where: { userId_date: { userId, date } },
  });
}
```

### 1.5 API Changes

**`GET /api/entries`** — add `?month=YYYY-MM` filter:

```
GET /api/entries?month=2026-03
```

- Validate format: `/^\d{4}-\d{2}$/` → `400 "Invalid month format. Use YYYY-MM"` if invalid
- Pass to `getAllEntries(userId, month)`
- No `month` param → returns all entries (unchanged behavior)

**`POST /api/entries`** — accept optional `date` field:

Request body:
```typescript
{
  mentalEnergy: number;
  physicalEnergy: number;
  mentalNote?: string | null;
  physicalNote?: string | null;
  date?: string;  // "YYYY-MM-DD" — omit for today
}
```

Validation additions:
- If `date` provided, parse as `toMidnightUTC(new Date(date + "T00:00:00Z"))`
- Reject if parsed date is after `toMidnightUTC(new Date())` → `400 "Cannot create entries for future dates"`
- Check for existing entry using `getEntryByDate` → `409 "An entry already exists for this date"`

**New: `PUT /api/entries/[id]`** (`app/api/entries/[id]/route.ts`):

```
PUT /api/entries/42
```

Request body:
```typescript
{
  mentalEnergy: number;
  physicalEnergy: number;
  mentalNote?: string | null;
  physicalNote?: string | null;
}
```

- Same score validation as other endpoints (1–6, 8–10; reject 7)
- Parse `id` from route params → `400` if not a valid integer
- Call `updateEntryById(userId, id, data)`
- Catch `PrismaClientKnownRequestError` with code `P2025` → `404 "Entry not found"`
- Response: updated `EnergyEntry`

**Unchanged:** `GET /api/entries/today`, `PUT /api/entries/today`

### 1.6 Component: `CheckInForm.tsx`

This is the most important component change in Phase 1.

**Problem:** The URL is currently hard-coded as `isEditing ? "/api/entries/today" : "/api/entries"`.

**New props:**

```typescript
interface CheckInFormProps {
  initialEntry?: EnergyEntry;  // existing entry to edit (uses its id for PUT URL)
  targetDate?: Date;           // backfill: the past date to create an entry for
  onCancel?: () => void;
  onSaved?: (entry: EnergyEntry) => void;
}
```

**URL derivation:**

```typescript
const url = initialEntry
  ? `/api/entries/${initialEntry.id}`
  : "/api/entries";
const method = initialEntry ? "PUT" : "POST";
```

**POST body when `targetDate` provided** (backfill):

```typescript
// targetDate is a Date object from the calendar — its local date is what the user sees
// Send as YYYY-MM-DD using UTC date parts (date field is normalized to midnight UTC)
const dateStr = [
  targetDate.getUTCFullYear(),
  String(targetDate.getUTCMonth() + 1).padStart(2, "0"),
  String(targetDate.getUTCDate()).padStart(2, "0"),
].join("-");

body: JSON.stringify({ mentalEnergy, physicalEnergy, mentalNote, physicalNote, date: dateStr })
```

**Button label:**

```typescript
const label = submitting
  ? "Saving..."
  : initialEntry
    ? "Update energy"
    : targetDate
      ? `Log energy for ${formatShortDate(targetDate)}`
      : "Log today's energy";
```

Import `EnergyEntry` from `lib/types.ts` and `formatShortDate` from `lib/dates.ts`.

function handleSaved(saved: EnergyEntry) {
  setEntries(prev => {
    const exists = prev.find(e => e.id === saved.id);
    return exists
      ? prev.map(e => e.id === saved.id ? saved : e)   // replace updated

  });

## Edge Cases

| Scenario | Handling |
|---|---|
| Future date backfill | `400` from API; `disabled={{ after: new Date() }}` in DayPicker blocks UI |
| Duplicate entry for same date | `409` from API; modal shows "view" not "create" for existing days (UI prevents it) |
| Editing another user's entry by ID | `where: { id, userId }` in Prisma → `P2025` → `404` |
| Timezone: user in UTC-8 at 11 PM | Client sends YYYY-MM-DD from calendar click (local date shown on calendar); server parses as `T00:00:00Z` → correct midnight UTC |
| Score of 7 submitted | `400 "Score of 7 is not allowed"` (unchanged from existing validation) |
| `updateTodayEntry` (home page edit) | Continues to work — now delegates to `updateEntryById` internally |
| Empty month navigation | Fetching a month with no entries returns `[]`; calendar shows no dots |
| Prisma `P2025` in `updateEntryById` | Route catches and returns `404 "Entry not found"` |
