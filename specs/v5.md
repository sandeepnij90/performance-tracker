# v5 Spec: Journal Calendar View with Backfill

## Overview

v5 adds a **Calendar View** to the journal history page, matching the existing energy audit calendar pattern. Users can:

1. Toggle between **List** and **Calendar** views on the history page
2. See visual indicators on dates with journal entries (solid dot = complete, faded dot = morning only)
3. Click any past date to **backfill** a missed journal entry (morning intention first, then evening reflection)
4. Click a date with an existing entry to **view or edit** it

The journal's two-step flow (morning → evening) is handled by a modal state machine that guides the user through both steps when backfilling.

### User Flow Summary

```
Journal History Page
  ├── List view (default) — same as current behavior
  └── Calendar view
        ├── Click empty past date → Modal: create-morning
        │     └── Save morning → Modal: create-evening
        │           ├── Complete evening → save & close
        │           └── Skip → close with morning-only entry
        ├── Click date with entry → Modal: view
        │     ├── Edit morning → edit form → save → back to view
        │     └── Edit evening → edit form → save → back to view
        └── Future dates → disabled (unclickable)
```

### Phase 2 — JournalCalendarView Component

**Create:** `components/JournalCalendarView.tsx`

Mirrors `components/CalendarView.tsx` but for `JournalEntry`:

Props:
```typescript
interface JournalCalendarViewProps {
  entries: JournalEntry[];
  onDayClick: (date: Date, entry: JournalEntry | null) => void;
}
```

Key differences from `CalendarView.tsx`:
- Builds `entryMap: Map<string, JournalEntry>` via `useMemo`
- Computes two date arrays: `completeDates` (where `achieved !== null`) and `partialDates` (where `achieved === null`)
- Uses `modifiers={{ journalComplete: completeDates, journalPartial: partialDates }}`
- Uses `modifiersClassNames={{ journalComplete: "rdp-day-journal-complete", journalPartial: "rdp-day-journal-partial" }}`
- Same `DayPicker` config: `disabled={{ after: new Date() }}`, `endMonth`, `fixedWeeks`, `showOutsideDays`, `weekStartsOn={1}`

Reuses: `toMidnightUTC` from `lib/dates.ts`, `JournalEntry` from `lib/types.ts`

### Phase 3 — JournalDayModal Component

**Create:** `components/JournalDayModal.tsx`

Props:
```typescript
interface JournalDayModalProps {
  date: Date;
  entry: JournalEntry | null;
  onClose: () => void;
  onSaved: (entry: JournalEntry) => void;
}
```

Mode state machine:
```typescript
type Mode = "view" | "edit-morning" | "edit-evening" | "create-morning" | "create-evening";
// Initial mode: entry ? "view" : "create-morning"
```

Mode behavior:
| Mode | Renders | On save transition |
|------|---------|-------------------|
| `create-morning` | `MorningForm` with `targetDate={date}` | Store entry → `create-evening` |
| `create-evening` | Morning read-only + `EveningForm` + Skip button | Call `onSaved` → close |
| `view` | `JournalEntryCard` + edit buttons | N/A |
| `edit-morning` | `MorningForm` with `initialEntry` + cancel | Update entry → `view` |
| `edit-evening` | `EveningForm` with cancel | Update entry → `view` |

Modal shell (matches `components/DayModal.tsx`):
- Fixed overlay with `bg-black/60`
- Escape key handler
- Click-outside-to-close
- `max-w-md` width (wider than energy modal's `max-w-sm` since journal content is longer)
- `max-h-[80vh] overflow-y-auto` on inner div for scrolling

Reuses: `MorningForm`, `EveningForm`, `JournalEntryCard`, `formatEntryDate`

### Phase 4 — JournalHistoryView Component

**Create:** `components/JournalHistoryView.tsx`

Mirrors `components/HistoryView.tsx`:

Props:
```typescript
interface JournalHistoryViewProps {
  entries: JournalEntry[];
}
```

State:
- `view: "list" | "calendar"` — toggle state
- `entries: JournalEntry[]` — mutable copy for optimistic updates
- `modalState: { date: Date; entry: JournalEntry | null } | null`

Renders:
- List/Calendar toggle buttons (same styling as `HistoryView.tsx`)
- List mode: `JournalEntryCard` for each entry with `formatEntryDate` title
- Calendar mode: `JournalCalendarView`
- Modal: `JournalDayModal` when `modalState` is set

`handleSaved` logic (same pattern as `HistoryView.tsx`):
- Check if entry ID exists in array → update in place
- Otherwise insert and sort by date descending
- Close modal

### Phase 5 — Update History Page

**Modify:** `app/journal/history/page.tsx`

Replace inline `JournalEntryCard` list rendering with:
```tsx
<JournalHistoryView entries={entries} />
```

Page remains a server component. Remove direct `JournalEntryCard` import and `formatEntryDate` import (both move into `JournalHistoryView`).
