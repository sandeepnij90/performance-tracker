# Energy Tracker — V2 Specification

**Version:** 2.0
**Date:** 2026-03-17
**Builds on:** specs/spec.md (MVP, Phases 1–6)

---

## Overview

V2 introduces multi-user support via NextAuth.js v5 (Auth.js). Each user gets their own isolated set of energy entries. Sign-in uses Google OAuth.

---

## Goals

- Allow multiple users to track energy independently
- Protect all routes and API endpoints behind authentication
- Keep the existing UI and UX intact — auth should wrap the app, not reshape it
- Use NextAuth.js v5 (Auth.js) for self-hosted auth with no third-party service dependency

---

## Constraints & Assumptions

- NextAuth.js v5 (`next-auth@beta`) is the auth library. See https://authjs.dev/getting-started
- Google OAuth is the only sign-in method
- JWT session strategy (no database session table needed)
- Auth.js database tables (User, Account) managed via `@auth/prisma-adapter`
- Existing MVP entries (created without a userId) were deleted during the Phase 1 migration
- The `lib/db.ts` service layer already exists — adding `userId` filtering is a natural extension

## Phases

---

### Phase 1 — NextAuth Setup & Schema Migration ✅

**Goal:** Install Auth.js, add the required database models, and add user ownership to EnergyEntry.

#### Tasks

1. Install `next-auth@beta`, `@auth/prisma-adapter`
2. Add Auth.js models to Prisma schema (User, Account)
3. Make `EnergyEntry.userId` a non-nullable foreign key to `User`
4. Run migration (delete orphaned entries, then apply NOT NULL constraint)
5. Create `auth.ts` in the project root — configure Auth.js with:
   - `@auth/prisma-adapter`
   - Google OAuth provider
   - JWT session strategy
6. Create `app/api/auth/[...nextauth]/route.ts` — export `GET` and `POST` from `auth.ts`
7. Add environment variables to `.env` and `.env.example`:
   - `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`

#### Schema Additions

```prisma
model User {
  id            String        @id @default(cuid())
  name          String?
  email         String?       @unique
  emailVerified DateTime?
  image         String?
  accounts      Account[]
  entries       EnergyEntry[]
}

model Account {
  id                String  @id @default(cuid())
  userId            String
  type              String
  provider          String
  providerAccountId String
  refresh_token     String?
  access_token      String?
  expires_at        Int?
  token_type        String?
  scope             String?
  id_token          String?
  session_state     String?
  user              User    @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([provider, providerAccountId])
}

model EnergyEntry {
  id             Int      @id @default(autoincrement())
  createdAt      DateTime @default(now())
  mentalEnergy   Int
  mentalNote     String?
  physicalEnergy Int
  physicalNote   String?
  userId         String
  user           User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, createdAt])
}
```

#### Acceptance Criteria

- [x] `next-auth@beta` and `@auth/prisma-adapter` are installed
- [x] User and Account tables exist in the database
- [x] `EnergyEntry.userId` is a non-nullable foreign key to `User`
- [x] `auth.ts` is configured with Google OAuth provider

### Phase 2 — Sign-In UI & Route Protection

**Goal:** Build sign-in page and protect routes with middleware.

#### Pages

| Route      | Description                    |
| ---------- | ------------------------------ |
| `/sign-in` | "Sign in with Google" button   |

#### Tasks

1. Create `app/sign-in/page.tsx` — client component with a Google sign-in button that calls `signIn("google")`
2. Add Auth.js middleware (`middleware.ts`) to protect all routes except `/sign-in` and `/api/auth`
3. Add `authorized` callback to `auth.ts` for middleware integration
4. After sign-in, redirect to `/`; after sign-out, redirect to `/sign-in`

#### Acceptance Criteria

- [ ] Users can sign in with Google
- [ ] Unauthenticated users are redirected to `/sign-in`

---

### Phase 3 — Scope Data to Authenticated User

**Goal:** Ensure each user only sees and modifies their own entries.

#### Tasks

1. Update all functions in `lib/db.ts` to accept a `userId` parameter:
   - `createEntry(userId, data)`
   - `getAllEntries(userId)`
   - `getTodayEntry(userId)`
   - `updateTodayEntry(userId, data)`
2. Update all API routes to extract `userId` from `auth()` and pass to service functions
3. Update server components (`app/page.tsx`, `app/history/page.tsx`) to get `userId` from `auth()` and pass to service functions

#### Acceptance Criteria

- [ ] User A cannot see or modify User B's entries
- [ ] Home page and history page only show the current user's data

---

### Phase 4 — Header & Session UI

**Goal:** Add user info and sign-out to the app navigation.

#### Tasks

#### Acceptance Criteria

- [ ] Signed-in user's name or email is visible in the header
- [ ] Sign-out button works and redirects to sign-in
